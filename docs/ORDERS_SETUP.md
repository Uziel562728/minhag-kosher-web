# Configuración del Sistema de Pedidos y Base de Datos

Este documento detalla los pasos necesarios para configurar el nuevo flujo de pedidos de **Super Market Kosher**, migrando del envío por WhatsApp a un sistema transaccional robusto en el backend con Supabase y notificaciones push vía Firebase Cloud Messaging.

---

## ⚠️ Riesgos de Seguridad Detectados

> [!WARNING]
> **Modelo de Administradores Actual:**
> En las políticas de Row Level Security (RLS) actuales de las tablas `categories` y `products` (y ahora también en `orders` y `order_items`), cualquier usuario que esté **autenticado** (sin importar su rol o correo electrónico) se considera administrador y obtiene permisos totales de escritura y lectura.
>
> **Recomendación:** Se debería implementar un sistema de roles en Supabase (por ejemplo, mediante una columna `role` en una tabla de perfiles de usuario vinculada a `auth.users`, o usando Supabase Custom Claims) para asegurar que solo usuarios con rol de administrador tengan acceso al panel de administración y a los pedidos.

---

## 1. Migración de Base de Datos (SQL)

Ejecuta el siguiente código en el **SQL Editor** de tu consola de Supabase. Este script creará de forma atómica e idempotente las tablas de pedidos, sus restricciones, políticas de RLS y la función RPC transaccional.

```sql
-- 1. Crear Tabla de Pedidos (public.orders)
create table if not exists public.orders (
    id uuid primary key default gen_random_uuid(),
    order_number bigint generated by default as identity unique,
    customer_name text not null,
    customer_phone text not null,
    shipping_method text not null check (shipping_method in ('retiro', 'envio')),
    street text,
    floor text,
    department text,
    status text not null default 'pending' check (status in ('pending', 'confirmed', 'preparing', 'ready', 'delivered', 'cancelled')),
    subtotal numeric(12,2) not null check (subtotal >= 0),
    total numeric(12,2) not null check (total >= 0),
    customer_notes text,
    idempotency_key text unique,
    created_at timestamptz not null default now(),
    updated_at timestamptz not null default now()
);

-- Restricción para obligar calle cuando shipping_method = 'envio'
alter table public.orders drop constraint if exists check_shipping_street;
alter table public.orders add constraint check_shipping_street 
    check (shipping_method <> 'envio' or (street is not null and trim(street) <> ''));

-- 2. Crear Tabla de Ítems de Pedidos (public.order_items)
create table if not exists public.order_items (
    id uuid primary key default gen_random_uuid(),
    order_id uuid not null references public.orders(id) on delete cascade,
    product_id uuid references public.products(id) on delete set null,
    product_name text not null,
    product_brand text,
    unit_price numeric(12,2) not null check (unit_price >= 0),
    quantity integer not null check (quantity > 0),
    subtotal numeric(12,2) not null check (subtotal >= 0),
    created_at timestamptz not null default now()
);

-- 3. Activar RLS en ambas tablas
alter table public.orders enable row level security;
alter table public.order_items enable row level security;

-- 4. Definir Políticas de Acceso (Solo administradores autenticados)
drop policy if exists "Allow authenticated admins to manage orders" on public.orders;
create policy "Allow authenticated admins to manage orders" on public.orders
    for all to authenticated using (true) with check (true);

drop policy if exists "Allow authenticated admins to manage order items" on public.order_items;
create policy "Allow authenticated admins to manage order items" on public.order_items
    for all to authenticated using (true) with check (true);

-- 5. Crear la Función PostgreSQL RPC Transaccional (create_order_transaction)
create or replace function public.create_order_transaction(
    p_customer_name text,
    p_customer_phone text,
    p_shipping_method text,
    p_street text,
    p_floor text,
    p_department text,
    p_customer_notes text,
    p_idempotency_key text,
    p_subtotal numeric,
    p_total numeric,
    p_items jsonb
)
returns table (
    id uuid,
    order_number bigint,
    total numeric,
    created_at timestamp with time zone
)
language plpgsql
security definer
as $$
declare
    v_order_id uuid;
    v_order_number bigint;
    v_created_at timestamp with time zone;
    v_existing_id uuid;
    v_existing_order_number bigint;
    v_existing_total numeric;
    v_existing_created_at timestamp with time zone;
begin
    -- Comprobación de idempotencia (solicitudes duplicadas)
    if p_idempotency_key is not null then
        select o.id, o.order_number, o.total, o.created_at
        into v_existing_id, v_existing_order_number, v_existing_total, v_existing_created_at
        from public.orders o
        where o.idempotency_key = p_idempotency_key
        limit 1;
        
        if found then
            return query select v_existing_id, v_existing_order_number, v_existing_total, v_existing_created_at;
            return;
        end if;
    end if;

    -- Insertar el pedido en 'orders'
    insert into public.orders (
        customer_name,
        customer_phone,
        shipping_method,
        street,
        floor,
        department,
        customer_notes,
        idempotency_key,
        subtotal,
        total
    ) values (
        p_customer_name,
        p_customer_phone,
        p_shipping_method,
        p_street,
        p_floor,
        p_department,
        p_customer_notes,
        p_idempotency_key,
        p_subtotal,
        p_total
    )
    returning public.orders.id, public.orders.order_number, public.orders.created_at
    into v_order_id, v_order_number, v_created_at;

    -- Insertar ítems en 'order_items'
    insert into public.order_items (
        order_id,
        product_id,
        product_name,
        product_brand,
        unit_price,
        quantity,
        subtotal
    )
    select
        v_order_id,
        case 
            when (item->>'product_id') is not null and (item->>'product_id') <> '' then (item->>'product_id')::uuid 
            else null 
        end,
        item->>'product_name',
        item->>'product_brand',
        (item->>'unit_price')::numeric,
        (item->>'quantity')::integer,
        (item->>'subtotal')::numeric
    from jsonb_array_elements(p_items) as item;

    return query select v_order_id, v_order_number, p_total, v_created_at;
end;
$$;
```

## 2. Despliegue de la Edge Function (`create-order`)

Para desplegar la función de Supabase Edge en producción, sigue estos pasos utilizando la CLI de Supabase:

### Comandos de Despliegue:

1. **Iniciar sesión en Supabase CLI** (si aún no lo has hecho):
   ```bash
   supabase login
   ```

2. **Desplegar la función**:
   ```bash
   supabase functions deploy create-order --project-ref tu-referencia-de-proyecto
   ```

## 3. Variables de Entorno y Secretos Necesarios

### Backend (Supabase Edge Function Secretos)

Debes registrar los siguientes secretos en tu proyecto de Supabase para que la Edge Function pueda enviar notificaciones push a través de Firebase Cloud Messaging (FCM) v1.

Puedes hacerlo ejecutando el siguiente comando en la CLI:
```bash
supabase secrets set --project-ref tu-referencia-de-proyecto FIREBASE_PROJECT_ID="tu-proyecto-id" FIREBASE_CLIENT_EMAIL="tu-email-de-servicio@gserviceaccount.com" FIREBASE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n..."
```

O directamente en el Panel de Supabase (**Project Settings** -> **Edge Functions** -> **Add Secret**):

| Clave | Descripción |
|---|---|
| `FIREBASE_PROJECT_ID` | El ID del proyecto de Firebase. |
| `FIREBASE_CLIENT_EMAIL` | El correo de la cuenta de servicio con permisos de FCM. |
| `FIREBASE_PRIVATE_KEY` | La clave privada del certificado de Firebase (debe incluir `\n`). |
| `ALLOWED_ORIGINS` | *(Opcional)* Orígenes CORS permitidos (separados por comas, ej: `http://localhost:5173,https://tusitio.com`). Si no se define, permite todos (`*`). |

> [!NOTE]
> La Edge Function funciona perfectamente aunque FCM no esté configurado (el pedido se guarda con éxito y la función registra un aviso en los logs en lugar de fallar).

## 4. Instrucciones para Probar el Sistema

Una vez ejecutada la migración SQL y desplegada la Edge Function:

1. **Probar el flujo normal de compra**:
   - Agrega productos al carrito.
   - Completa el formulario de checkout.
   - Presiona "Confirmar Pedido".
   - Valida que se limpie el carrito y aparezca la pantalla de éxito con el `# de pedido` y el `total`.
   - Verifica en la base de datos de Supabase que el pedido aparezca en la tabla `orders` y sus productos en `order_items`.

2. **Probar protecciones**:
   - **Carrito vacío:** Intenta forzar el envío del formulario con el carrito vacío. El botón se desactiva y el sistema previene la acción.
   - **Campos obligatorios:** Deja el campo de dirección vacío al elegir **Envío a Domicilio** y comprueba que se muestren alertas de validación.
   - **Manipulación de Precios:** Agrega un producto, usa las DevTools del navegador para modificar su precio en el estado local de React, y finaliza el pedido. Comprueba en la base de datos que el precio real guardado corresponda al de la tabla `products` y no al manipulado.
   - **Doble clic/Repetición:** Presiona repetidamente el botón de confirmación. Gracias a la idempotencyKey generada por intento, el backend devolverá el mismo pedido ya creado y evitará registros duplicados.

3. **Panel de Administración**:
   - Accede a `/admin/orders` tras iniciar sesión.
   - Visualiza las tarjetas de estadísticas.
   - Expande un pedido para ver la información de entrega, notas y el desglose de productos.
   - Cambia el estado de un pedido (ej. de `pending` a `confirmed`) y comprueba que se guarda al instante.
   - Abre el sitio en dos pestañas diferentes, crea un pedido en una y verifica que en el panel admin de la otra pestaña se añade en tiempo real (gracias al Realtime de Supabase).
